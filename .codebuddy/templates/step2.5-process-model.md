# Step 2.5 业务流程与功能建模

> 本步把 Step 2 的抽象方案翻译成清晰的业务模型，作为 Step 2.6 页面规划的依据。本步只梳理业务层，**不碰页面、不碰 UI**。

## 1. 业务流程图

> 梳理主流程 + 异常分支，标注触发条件与流转关系。可用流程图或文字步骤表达。

**主流程**：
1. 触发条件：{…}
2. 步骤 1：…
3. 步骤 2：…
4. 结束：…

**异常分支**：
- 分支 A：当 {条件} 时 → {处理}
- 分支 B：当 {条件} 时 → {处理}

> 颗粒度：业务功能模块级（如"订单管理""支付""退款"），非可操作功能点级。可操作功能点级细化留给 PRD。

| # | 功能模块 | 说明 | 对应业务流程 | 优先级 |
|---|---------|------|-------------|--------|
| 1 | | | 主流程 / 分支 A | 必须 / 后续 |

## 3. 业务对象状态机

> 建模核心业务对象的状态流转，确保分支闭合（无悬空状态）。

**对象**：{如 订单}

```
[待支付] --用户支付--> [已支付] --商家发货--> [已发货] --用户确认--> [完成]
   |                      |                       |
   |--超时未付--> [已取消]  |--用户申请退款--> [退款中]  |--用户拒收--> [已退货]
                         |--商家拒绝退款--> [已拒绝]
```

| 当前状态 | 事件 | 目标状态 | 触发角色 |
|---------|------|---------|---------|
| 待支付 | 用户支付 | 已支付 | 买家 |
| 待支付 | 超时未付 | 已取消 | 系统 |
| 已支付 | 用户申请退款 | 退款中 | 买家 |

## 4. 角色权限分布（业务角色）

> 业务角色（非系统权限配置），明确各角色可走哪些流程分支。

| 角色 | 可执行操作 | 可走流程分支 | 不可走 |
|------|-----------|-------------|--------|
| 买家 | 下单、支付、申请退款、确认收货 | 主流程、退款分支 | — |
| 卖家 | 发货、审核退款 | 发货、退款审核 | 下单 |
| 管理员 | 强制取消、强制退款 | 全部分支 | — |

- [ ] 状态机分支闭合（无悬空状态）
- [ ] 角色权限边界清晰（各角色可走的流程分支明确）
