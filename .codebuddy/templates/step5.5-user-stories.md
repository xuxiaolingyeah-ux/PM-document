# Step 5.5 用户故事列表（需求拆分）

> 本模板由 AI 在 Step 5 评审通过后，基于 Step 4 PRD + Step 5 评审结论生成。产出可直接导入 Jira。

## 填写说明

- **颗粒度**：用户故事（User Story）层，**不拆到 Task 级**（技术实现单元由研发在 Jira 中自行拆派）
- **标准句式**：作为 `<角色>`，我希望 `<功能>`，以便 `<价值>`
- **优先级**：P0 / P1 / P2（或 MoSCoW：Must / Should / Could）
- **每个故事**必须可独立交付、可独立验收
- **范围**：不新增 PRD 外需求，不修改评审已确认的 PRD 内容

## 用户故事列表

| # | 用户故事（As a... I want... So that...） | 优先级 | 对应 PRD 功能 | 大概内容 / 验收要点 |
|---|------------------------------------------|--------|--------------|---------------------|
| US-1 | 作为 `<角色>`，我希望 `<功能>`，以便 `<价值>` | P0 | 功能模块 A | 1. 验收要点… 2. 验收要点… |
| US-2 | 作为 `<角色>`，我希望 `<功能>`，以便 `<价值>` | P1 | 功能模块 B | 1. 验收要点… |
| US-3 | 作为 `<角色>`，我希望 `<功能>`，以便 `<价值>` | P2 | 功能模块 C | 1. 验收要点… |

## 拆分原则

- 一个故事对应一个**可独立交付、可验收**的价值点，避免"和故事"（把多个价值点塞进一个）
- 覆盖 PRD 全部功能清单，但**不新增** PRD 范围外的需求
- **不修改**评审已确认的 PRD 内容（有争议回退到 Step 5 或 Step 4）
- Task 级（接口、表结构、组件等实现单元）由研发在 Jira 中自行拆派，本步不触及

## 质量门禁自检

- [ ] 用户故事覆盖 PRD 全部功能清单
- [ ] 每个故事优先级已标注
- [ ] 每个故事可独立验收（有验收要点）
- [ ] 范围未超出 PRD
- [ ] 句式规范（As a / I want / So that 齐全）
- [ ] 可直接导入 Jira（字段齐全，无需二次加工）

---

## 完成后：导入 Jira → 生成测试用例文档

1. 用户故事确认后直接导入 Jira，研发可立即开工
2. 导入完成后，AI 基于每个故事的验收要点自动生成独立的测试用例文档（正常流程 + 边界场景 + 异常场景）
